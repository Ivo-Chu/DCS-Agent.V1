## Step 2 身份链路源码分析（只读，2026-09-22 晚）
- **核心事实**：DCS `Employee.UserId` 字段 = 企微 userid（Employee.cs:384 注释"对应企业微信中的UserId(OA表)"），表名 `S2_Employee`
- 现成 BLL 映射：`EmployeeSet.GetEmpCode(userId)`（数字 userid → Employee.UserId → Code 工号；非数字 userid 如 COMDGJWT 本身即工号）；反向 `GetUserId(empCode)`
- HTTP API 摸底：`OAController.GetEmpCode(userId)` 逻辑完全匹配但走 `[RequestAuthorize]` 用户 ticket；`DCSController.GetEmpCodeByWeiXinCode(code)` 走 `[ThirdToken]` 但输入是 OAuth code（一次性 5 分钟，机器人场景拿不到，不适用）；`EmployeeController.GetEmpCode(name, idCard)` 按姓名身份证，不适用 → **无免认证 userid→工号 HTTP 接口**
- ThirdToken 机制：AccountController.GetThirdToken 配合，DES 加密 {AppId,Time}，校验 ThirdAppAccount 表（appid/IP 白名单/URL 权限/有效期）；给 OA 接口加 ThirdToken 需改 DCS 源码——方案禁止
- **用户拒绝了读取 Web.config 连接串**（正确，凭据敏感）——数据库类型/凭据待用户告知
- 结论：最短路径 = 最小数据库只读查询 S2_Employee（UserId→Code/Name/DeptCode），凭据由用户手动配置；等用户给数据库类型+只读账号
